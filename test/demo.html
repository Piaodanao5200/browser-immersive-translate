Why Bilingual Reading Beats Translation Apps

A short note on keeping the original text in view while you learn.

Reading a foreign language article used to mean one of two things: copying paragraphs into a translation tool, or accepting whatever the browser produced when it replaced the page entirely. Both approaches throw away the original wording, and with it the context that makes reading worthwhile.

A better arrangement keeps the source text exactly where it is and places the translation directly beneath it. Nothing moves, nothing disappears, and your eye can travel from one to the other in a single glance. This is the same trick subtitles use, and it works for the same reason: comparison is cheaper than recall.

Three practical advantages

  • Terminology stays visible, so you can check how a specific phrase was handled.
  • Layout is preserved, which matters for documentation, tables and technical diagrams.
  • You can turn it off instantly and keep reading the original without reloading.
The goal is not to remove the foreign language from the page. The goal is to put it within reach.

How the rendering layer works

Each block of text is collected, filtered and sent to a translation service in small batches. When a batch comes back, a new element is appended inside the original block, styled to read as a subtitle. The original text nodes are never touched, so the page's own styling and event handlers keep working. 

const units = collectUnits(document.body);
for (const chunk of chunked(units, 6)) {
  const results = await translate(chunk.map(u => u.text));
  chunk.forEach((u, i) => render(u, results[i]));
}

Element Reason
